# SPK S3.7d/3b2b2k/2: Versioned Core Transition v0

Status: **EXPERIMENTAL; not frozen; not a full scheduler**.

## Purpose

Execute an actual frozen Core v0 batch against a **separate, immutable,
versioned neuron-state image**. This is not a projection of `ObservedExecutionV0`
and it does not call `run_network_v0`: that frozen Network runtime is used only
by independent tests as the functional reference.

- `initialize_neuron_image_v0` creates state `(raw=initial_raw, last_timestamp=0,
  version=0)` for each neuron in a canonical ordering, bound to a network and
  epoch. Node state is persistent; the Core guard remains transient per batch.
- `prepare_core_transition_v0` computes through the frozen `run_core_batch`
  entry point but changes **no** state.
- `commit_core_transition_v0` verifies the expected epoch, current node version,
  initial raw and timestamp, **recomputes Core result** to reject forged
  staged outputs/state, then writes a new immutable image and emits a local
  commit receipt. A replayed/stale preparation is rejected.
- Per-neuron batches are canonical `(EVENT_TIME, node_id, sorted channels)` and
  channel multiplicity must be retained; on a neuron, the same EVENT_TIME is
  processed only once. EVENT_TIME is not SERVICE_TIME.

## Important boundaries

**No service request is confirmed here.** The local receipt is a versioned
state-image write *only*, not an authenticated `STATE_COMMIT` service receipt.
The caller still has to prove that the correct request finished its units of
service, that program/state reads occurred, and that required OUTPUT capacity
was reserved before making a state transition visible.

`candidate_outputs` are generated by the frozen Core, but **have not been
published** in OUTPUT or routed, and cannot be treated as delivered spikes.
Until atomic output admission and service scheduling are integrated, there is
no guarantee of end-to-end no-loss under backpressure.

A caller can construct a fake `VersionedNeuronImageV0` from Python; this module
checks structural and version consistency but cannot authenticate image history
or prevent malicious direct dataclass construction. The future single-owner
scheduler must own and version the actual image exclusively.

## Validation & following phase

The dedicated tests compare independent Core transitions with `run_network_v0`
for networks without internal routes, as well as negative cases for forged
prepared results, replay, cross-epoch/network, malformed batches, and
untouched neighboring neuron state.

After validation, bind the local commit receipt to a completed
`STATE_COMMIT` request and authorized `PROGRAM_REFERENCE`/`STATE_LOAD`, then
integrate generation of output candidates with the pre-existing atomic OUTPUT
reservations and Memory Effect Authority. Only then attempt autonomous
multi-node network execution and deadlock classification.

No modification to frozen Core v0, Network v0, Compiler v0.
