# SPK Back Validation v1g: Native Original Route and Occurrence Lineage

Research-only, additive and non-promoting. **Do not modify frozen** Core, Network,
Compiler or Architecture v1 packages. v1g reads only the existing frozen native
v0e scheduler and A1 compute kernel and replays the original source fixture.

## Scientific purpose

v1e and v1f used a declared **hypothetical** translation of channel `7` from
sender A into channel `0` at each of B and C, with recipient computations
performed independently. That experimental construction is not evidence of
an actual route from A directly to both receivers. v1g resolves this narrowly
by inspecting the native original fixture's `fabric.static_routes`, actual
forward `occurrences`, sender `emissions`, receiving `batches`, and `parents`
ancestry. It also inspects the **reverse** feedback packet chain generated by
v0e on the original fixture. No network-level variant is executed.

## Attestation boundary

For every forward occurrence, v1g requires:

1. Exactly one matching static route by source, target, target channel,
   PE endpoints and per-edge delay, and a matching emitted source channel.
2. Per-edge emission/occurrence multiplicities match, including repeats.
3. Deliveries are strictly causal, parent occurrences target the current
   sender and were delivered before the descendant was emitted.
4. A forward batch consumes each delivered occurrence once, at its target.
5. OFF and ON `forward-first` runs have equal forward final states, emitted
   `(node, channel)` multisets, terminal payload multisets and directed route
   occurrence multisets (not assumed equal packet ids or timing).
6. A reverse feedback record cites a valid assessment and the forward edge
   directed from its receiver to its sender; a native flag named
   `independent_receiver` is **not** promoted into independent causal credit.

The report distinguishes for B and C: whether `A/7→recipient/0` is directly
present in static routes, whether it is actually used by the original forward
run, and whether the original run has a forward causal ancestry chain from A
through potentially multiple hops. **Never infer that A directly reaches C
merely because C is an ancestor-connected downstream recipient.**

The exact observed topology and counts must be read from the fwork JSON;
this package does **not** assert them in advance. In particular, the 2-hop
A→B→C structure in the isolated unit tests is merely a synthetic control.

The report may attest *original* runtime forward links and reverse evidence
lineage. It cannot attest any hypothetical variant-network route, receiver
utility, endogenous judgment, correct causal credit, a program update or
learning. The existing v1f preference policy remains experimenter-declared.

## Install

From `~/workspace/spk-backvalidation-v0`:

```bash
# place the downloaded incremental archive in ~/Scaricati/
tar -xzf ~/Scaricati/SPK_BV_v1g_Native_Original_Route_Lineage.tar.gz
bash search/spk_bv_v1g_research_gate.sh
```

## Native run (separate, source-pinned)

```bash
python -m search.spk_bv_v1g_native_route_lineage \
  --v1f /tmp/spk-bv-v1f-receiver-preference-polarity.json \
  --v1e /tmp/spk-bv-v1e-conditional-receiver-impact.json \
  --v1d /tmp/spk-bv-v1d-native-declared-criterion-13.json \
  --v1c /tmp/spk-bv-v1c-native-sensitivity.json \
  --v1b1 /tmp/spk-bv-v1b1-native-operator-replay.json \
  --v1a /tmp/spk-bv-v1a-symbolic-holdout.json \
  --v0w /tmp/spk-bv-v0w-native-13.json \
  --out /tmp/spk-bv-v1g-native-original-route-lineage.json
```

Safety: reference paths must be external to repository, regular non-symlinks,
non-aliased and size-bounded. Existing output is never overwritten; reruns use
new paths. Direct CLI imports the pinned native runtime only after validating
file paths, and validates full upstream native v1f recomputation before emitting
any report. The live **original** OFF/ON scheduler runs are additional.

## Follow-on research, not implied by v1g

1. Identify which **actual** recipients can causally originate feedback at
   which times and on which forward evidence. Do not assume votes are independent.
2. Define a criterion computed locally at a downstream neuron rather than an
   exogenous count policy, including its declared scope and time of availability.
3. Compare original and candidate sender behavior in a separate future network
   episode with traced interventions and an unchanged-control arm, without
   promoting the experimental variant to the frozen Architecture.
