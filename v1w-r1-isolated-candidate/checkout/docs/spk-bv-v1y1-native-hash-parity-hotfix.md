# SPK/BV v1y.1 - frozen native digest parity hotfix

## Symptom (fwork)

The fully inherited research gate succeeded, but running
`search.spk_bv_v1y_native_external_probe` rejected at:

`SPK BV v1y REJECTED: native probe comparison differs from v1x baseline`

## Root cause

v1p/v1x `native_result_sha256` is generated by `snapshot(result)`, which hashes
SPK's lossless type-tagged `canonical_fixture` encoded in compact canonical JSON.
The original v1y implementation incorrectly computed `sha256(canon(result))`.
`canon` is the *research report* pretty-print JSON serializer, whose bytes are
not the same as those of the frozen native snapshot; it also cannot preserve
all tuple/list distinctions. Both valid results can therefore have different
hashes even if no tracing interference occurred.

## Correction

`observed_pair` now captures the native run's lossless, type-tagged serialization
through `native_capture_v0k.canonical_fixture` + `_json_bytes` on each side of
`ScopedPythonProbe`. It compares these exact bytes, then computes the two
SHA-256 hashes. This is the *same byte contract* used by `snapshot(result)` in
v0t and by `native_arm`/`summarize` in v1p and v1x.

The listener is not source-owned, no native B control transport is installed,
no absence certificate, scored receiver judgment, operator update or learning
is asserted. The frozen scheduler, native fixture, Core, Network, Compiler and
Architecture remain unchanged. No v1x / v1w report needs to be regenerated.
